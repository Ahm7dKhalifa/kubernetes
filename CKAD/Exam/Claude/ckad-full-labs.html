Build a Container Image from a Dockerfile
Medium

Create a Dockerfile for a simple Python app, build the image, and run it as a Pod.

  • Create a file app.py that prints "Hello CKAD"
  • Write a Dockerfile using python:3.11-slim base
  • Build image tagged myapp:v1
  • Create a Pod myapp-pod using the image
# Step 1: Create app
echo 'print("Hello CKAD")' > app.py

# Step 2: Create Dockerfile
cat > Dockerfile <<EOF
FROM python:3.11-slim
WORKDIR /app
COPY app.py .
CMD ["python", "app.py"]
EOF

# Step 3: Build (if using minikube, point to minikube's docker)
eval $(minikube docker-env)
docker build -t myapp:v1 .

# Step 4: Create Pod (imagePullPolicy: Never to use local image)
kubectl run myapp-pod --image=myapp:v1 --restart=Never --image-pull-policy=Never
Dockerfile commands to knowFROM (base image), WORKDIR (set directory), COPY (add files), RUN (execute during build), CMD (default command), ENTRYPOINT (fixed command), EXPOSE (document port), ENV (set env var).

Multi-Container Pod — Sidecar Pattern
Medium

Create Pod sidecar-pod: app container writes logs to /var/log/app.log, sidecar container tails the same file. Use shared emptyDir volume.

apiVersion: v1
kind: Pod
metadata:
  name: sidecar-pod
spec:
  containers:
  - name: app
    image: busybox
    command: ["sh","-c","while true; do echo $(date) INFO request >> /var/log/app.log; sleep 3; done"]
    volumeMounts:
    - { name: logs, mountPath: /var/log }
  - name: sidecar
    image: busybox
    command: ["sh","-c","tail -f /var/log/app.log"]
    volumeMounts:
    - { name: logs, mountPath: /var/log }
  volumes:
  - name: logs
    emptyDir: {}
Verify: kubectl logs sidecar-pod -c sidecar

Create a Deployment with Rolling Update Strategy
Easy

Create Deployment web-deploy, image nginx:1.25, 3 replicas, with maxSurge=1, maxUnavailable=0.

Imperative + edit
Full YAML
# Generate skeleton
kubectl create deployment web-deploy --image=nginx:1.25 --replicas=3 --dry-run=client -o yaml > deploy.yaml
# Add strategy section, then apply
kubectl apply -f deploy.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-deploy
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: web-deploy
  template:
    metadata:
      labels:
        app: web-deploy
    spec:
      containers:
      - name: nginx
        image: nginx:1.25

Blue/Green Deployment Strategy
Hard

Implement blue/green: Deploy v1 (blue) behind a Service. Deploy v2 (green). Switch Service to v2.

# Blue deployment (v1)
kubectl create deployment blue --image=nginx:1.25
kubectl label deployment blue version=v1
kubectl expose deployment blue --name=web-svc --port=80 --selector=version=v1 --type=ClusterIP --dry-run=client -o yaml > svc.yaml
# Edit svc.yaml selector to: version: v1
kubectl apply -f svc.yaml

# Green deployment (v2)
kubectl create deployment green --image=nginx:1.26
kubectl label pods -l app=green version=v2 --overwrite

# Switch traffic: change Service selector from v1 to v2
kubectl patch svc web-svc -p '{"spec":{"selector":{"version":"v2"}}}'

# Verify: traffic now goes to green
kubectl describe svc web-svc | grep Selector
Blue/Green conceptBoth versions run simultaneously. The Service selector switches traffic instantly. Rollback = switch selector back to v1.

Add All 3 Probes to a Pod
Medium

Create Pod probed-pod (nginx, port 80) with: startup probe (30 failures × 10s), liveness (period 15s, timeout 3s), readiness (period 5s).

apiVersion: v1
kind: Pod
metadata:
  name: probed-pod
spec:
  containers:
  - name: nginx
    image: nginx
    ports: [{ containerPort: 80 }]
    startupProbe:
      httpGet: { path: /, port: 80 }
      failureThreshold: 30
      periodSeconds: 10
    livenessProbe:
      httpGet: { path: /, port: 80 }
      periodSeconds: 15
      timeoutSeconds: 3
      failureThreshold: 3
    readinessProbe:
      httpGet: { path: /, port: 80 }
      periodSeconds: 5

SecurityContext — Full Configuration
Medium

Create Pod secure-pod: run as user 1000, group 3000, read-only root filesystem, drop all capabilities, no privilege escalation. Mount emptyDir at /tmp for writable space.

apiVersion: v1
kind: Pod

  name: secure-pod
spec:
  securityContext:
    runAsUser: 1000
    runAsGroup: 3000

    fsGroup: 2000
  containers:
  - name: app
    image: nginx

      readOnlyRootFilesystem: true
      allowPrivilegeEscalation: false

    - { name: cache, mountPath: /var/cache/nginx }
    - { name: run, mountPath: /var/run }

  - { name: tmp, emptyDir: {} }

Troubleshoot Service — No Endpoints
Medium

Service broken-svc has no endpoints. Diagnose why.

Setup:

kubectl run web --image=nginx --labels="app=web"
kubectl create service clusterip broken-svc --tcp=80:80
# The service has selector app=broken-svc (wrong!)
# Step 1: Check endpoints
kubectl get endpoints broken-svc     # Empty!

# Step 2: Check Service selector
kubectl get svc broken-svc -o jsonpath='{.spec.selector}'
# {"app":"broken-svc"} — doesn't match Pod label "app=web"

# Step 3: Check Pod labels
kubectl get pods --show-labels

# Step 4: Fix — patch the Service selector
kubectl patch svc broken-svc -p '{"spec":{"selector":{"app":"web"}}}'

# Verify
kubectl get endpoints broken-svc     # Now shows Pod IP
Key ruleService selector must EXACTLY match Pod labels. Most common cause of "Service not working" = selector mismatch.

NetworkPolicy — Deny All Ingress
Medium

Create a NetworkPolicy in namespace secure-ns that denies ALL incoming traffic to Pods with label app=db.

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-ingress
  namespace: secure-ns
spec:
  podSelector:
    matchLabels:
      app: db
  policyTypes:
  - Ingress
  ingress: []            # Empty = deny all incoming
NetworkPolicy logicEmpty ingress: [] = deny all. No ingress field at all = no restriction. Specifying rules = allow only matching traffic.
