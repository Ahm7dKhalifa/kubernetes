Kubernetes Jobs – Deep & Simple Explanation

Section 1: Introduction

1. What is a Job?

A Kubernetes Job is a controller that ensures a Pod runs to completion successfully.

Unlike Deployment (which runs forever), Job runs a task once (or multiple times) and then stops.

Real Life Example

  • Database migration
  • Backup process
  • Sending batch emails
  • Data processing task

2. Job Benefits

  • ✔ Ensures task completes successfully
  • ✔ Automatically retries failed Pods
  • ✔ Can run multiple Pods in parallel
  • ✔ Handles crash recovery
  • ✔ Works well for batch processing

3. Job Types

1️⃣ Non-parallel Job

Runs one Pod once.

2️⃣ Parallel Job with Fixed Completion

Runs multiple Pods until a number of successful completions is reached.

3️⃣ Work Queue Job

Multiple Pods process tasks from shared queue.

Section 2: Job Management

Job Workflow Diagram

User applies YAML | v Kubernetes API Server | v Job Controller | v Creates Pod(s) | v Pods Execute Task | v Success? ----No----> Retry (Backoff Policy) | Yes | v Job Completed

1. Basic Job YAML File

apiVersion: batch/v1 kind: Job metadata: name: example-job spec: completions: 3 parallelism: 2 backoffLimit: 4 template: spec: restartPolicy: Never containers: - name: worker image: busybox command: ["sh", "-c", "echo Hello Kubernetes"]

Important Fields Explained

  • completions: Total successful Pods needed
  • parallelism: How many Pods run at same time
  • backoffLimit: Number of retries before failing
  • restartPolicy: Must be Never or OnFailure

2. Completions & Parallelism Explained

Example:

completions: 6 parallelism: 2
Meaning:
Time → Pod1 ████ Done Pod2 ████ Done Pod3 ████ Done Pod4 ████ Done Pod5 ████ Done Pod6 ████ Done
Only 2 run at same time until total 6 succeed.

3. Fixed Completion vs Work Queue

Fixed Completion

Each Pod performs identical task.

Work Queue

Pods pull tasks from queue (like Kafka, Redis, SQS).
Shared Queue / | \ Pod1 Pod2 Pod3 | | | Process Process Process

4. Handling Pod & Container Failures

If Pod fails: Kubernetes will: 1. Create new Pod 2. Retry until backoffLimit reached

Restart Policy

- Never → new Pod created - OnFailure → container restarts in same Pod

5. Backoff Failure Policy

Backoff means: Kubernetes waits longer between retries. Example: Retry 1 → after 10s Retry 2 → after 20s Retry 3 → after 40s If backoffLimit reached → Job marked Failed.

6. Pod Failure Policy (Advanced)

You can define rules: - Retry only on specific exit codes - Fail job immediately on certain errors Example:
podFailurePolicy: rules: - action: FailJob onExitCodes: operator: In values: [1]
Meaning: If container exits with code 1 → fail whole job.

7. Job Termination & Cleanup

After completion: Pods remain by default. You can auto-delete:
ttlSecondsAfterFinished: 100
This deletes job 100 seconds after completion.

8. Job Patterns

1️⃣ One-time Task

Simple job, runs once.

2️⃣ Parallel Batch Processing

Process large dataset in chunks.

3️⃣ Work Queue Consumer

Pods consume tasks dynamically.

4️⃣ CronJob

Runs Jobs on schedule. Example:
apiVersion: batch/v1 kind: CronJob metadata: name: daily-backup spec: schedule: "0 2 * * *"

Summary

  • Job = Run task until completion
  • Deployment = Run forever
  • Use completions for total runs
  • Use parallelism for concurrency
  • Use backoffLimit for retries
  • Use ttlSecondsAfterFinished for cleanup
Kubernetes Job is ideal for batch processing, migrations, and background tasks.
