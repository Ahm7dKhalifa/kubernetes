LAB 01
Create a Pod
4% ⏱ Target: 1 min
Context: kubectl config use-context k8s-ckad · Namespace: default

Create a Pod with the following requirements:

  • Pod name: web-pod
  • Image: nginx:1.25
  • Container port: 80
Verify
kubectl get pod web-pod
# Expected: STATUS = Running, READY = 1/1
Fastest method (1 command):
kubectl run web-pod --image=nginx:1.25 --port=80
Alternative — YAML method:
kubectl run web-pod --image=nginx:1.25 --port=80 --dry-run=client -o yaml | kubectl apply -f -
Why this approachFor simple Pods, the imperative kubectl run is faster than writing YAML. Save YAML for complex specs. The --port flag sets containerPort (informational only — doesn't expose anything).

LAB 04
Pod with Custom Command and Arguments
4% ⏱ Target: 2 min
Namespace: default

Create a Pod named cmd-pod with:

  • Image: busybox:1.36
  • Command: /bin/sh -c
  • Arguments: echo Hello CKAD && sleep 3600
  • The Pod should stay running (not complete immediately)
Verify
kubectl logs cmd-pod
# Expected: Hello CKAD

kubectl get pod cmd-pod
# Expected: STATUS = Running
Imperative:
kubectl run cmd-pod --image=busybox:1.36 --restart=Never -- /bin/sh -c "echo Hello CKAD && sleep 3600"
YAML equivalent:
apiVersion: v1
kind: Pod
metadata:
  name: cmd-pod
spec:
  restartPolicy: Never
  containers:
  - name: cmd-pod
    image: busybox:1.36
    command: ["/bin/sh", "-c"]
    args: ["echo Hello CKAD && sleep 3600"]
Exam TrapThe -- in kubectl separates kubectl flags from the container command. Everything after -- is the container's command + args. Without sleep 3600, the container exits immediately after echo and becomes Completed.
LAB 05
Sidecar Pattern — Log Shipping
7% ⏱ Target: 5 min
Namespace: default

Create a Pod named sidecar-pod with two containers:

  • Container 1 — app: image busybox, runs command that writes the current date to /var/log/app.log every 3 seconds
  • Container 2 — sidecar: image busybox, runs tail -f /var/log/app.log
  • Both containers share a volume mounted at /var/log
Verify
kubectl logs sidecar-pod -c sidecar
# Expected: date entries appearing every 3 seconds
apiVersion: v1
kind: Pod
metadata:
  name: sidecar-pod
spec:
  containers:
  - name: app
    image: busybox
    command: ["sh","-c","while true; do date >> /var/log/app.log; sleep 3; done"]
    volumeMounts:
    - name: logs
      mountPath: /var/log
  - name: sidecar
    image: busybox
    command: ["sh","-c","tail -f /var/log/app.log"]
    volumeMounts:
    - name: logs
      mountPath: /var/log
  volumes:
  - name: logs
    emptyDir: {}
Key PatternThis is the Sidecar pattern: both containers mount the same emptyDir volume. The app writes logs, the sidecar reads and ships them. emptyDir is created when Pod starts, deleted when Pod dies.

Pod with ConfigMap as Env Vars
7%⏱ Target: 4 min
Namespace: default

Step 1: Create a ConfigMap named app-config with DB_HOST=mysql and DB_PORT=3306.
Step 2: Create Pod config-pod with image nginx that loads all keys from app-config as environment variables.

Verify
kubectl exec config-pod -- env | grep DB_
# Expected: DB_HOST=mysql  DB_PORT=3306
# Step 1: Create ConfigMap
kubectl create configmap app-config --from-literal=DB_HOST=mysql --from-literal=DB_PORT=3306

# Step 2: Pod YAML (load ALL keys from ConfigMap)
apiVersion: v1
kind: Pod
metadata:
  name: config-pod
spec:
  containers:
  - name: app
    image: nginx
    envFrom:                 # Load ALL keys as env vars
    - configMapRef:
        name: app-config
envFrom vs envenvFrom loads ALL keys from a ConfigMap/Secret. env.valueFrom loads ONE specific key. Use envFrom when you want everything, valueFrom when you want to pick specific keys or rename them.

Security Context — Run as Non-Root
7%⏱ Target: 4 min
Namespace: default

Create Pod secure-pod with image nginx:

  • Must run as user ID 1000, group ID 3000
  • Read-only root filesystem
  • No privilege escalation allowed
  • Drop all Linux capabilities
Verify
kubectl get pod secure-pod -o jsonpath='{.spec.containers[0].securityContext}' | jq .
kubectl get pod secure-pod -o jsonpath='{.spec.securityContext}' | jq .
apiVersion: v1
kind: Pod

Tolerate a Tainted Node
7%⏱ Target: 4 min
Namespace: default

Step 1: Taint node minikube with dedicated=special:NoSchedule.
Step 2: Create Pod tolerant-pod with image nginx that tolerates this taint.
Step 3: Clean up — remove the taint after testing.

Verify
kubectl get pod tolerant-pod -o wide
# Expected: Running on minikube

# Step 2: Pod YAML with toleration
apiVersion: v1
kind: Pod
metadata:
  name: tolerant-pod
spec:
  tolerations:
  - key: "dedicated"
    operator: "Equal"
    value: "special"
    effect: "NoSchedule"
  containers:
  - name: nginx
    image: nginx
# Step 3: Remove taint (note the trailing minus sign)
kubectl taint nodes minikube dedicated=special:NoSchedule-
LAB 20
Node Affinity — Preferred
7%⏱ Target: 5 min
Namespace: default

Create Pod affinity-pod with image nginx. It should prefer (not require) nodes labeled zone=us-east-1a.

Verify
kubectl get pod affinity-pod -o jsonpath='{.spec.affinity}' | jq .
# Expected: preferredDuringSchedulingIgnoredDuringExecution with zone=us-east-1a
apiVersion: v1
kind: Pod
metadata:
  name: affinity-pod
spec:
  affinity:
    nodeAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        preference:
          matchExpressions:
          - key: zone
            operator: In
            values:
            - us-east-1a
  containers:
  - name: nginx
    image: nginx
Preferred vs Requiredpreferred = scheduler tries but schedules elsewhere if no match (Pod runs anyway). required = Pod stays Pending forever if no match. Use kubectl explain pod.spec.affinity.nodeAffinity during the exam to get the exact field names.

  • Image: nginx:1.25, Port: 80
  • Labels: app=web, env=production
  • CPU request: 100m, limit: 200m. Memory request: 64Mi, limit: 128Mi
  • Liveness probe: HTTP GET / port 80, period 10s
  • Readiness probe: HTTP GET / port 80, period 5s
  • Environment variable APP_ENV=production
  • Run as user 1000, read-only root filesystem
  • Grace period: 45 seconds
  • Mount an emptyDir at /tmp (for writable temp space)
Verify
kubectl -n production get pod prod-app
# Expected: Running 1/1

kubectl -n production get pod prod-app -o jsonpath='{.status.qosClass}'
# Expected: Burstable

kubectl -n production describe pod prod-app | grep -E "Liveness|Readiness|security"
kubectl create namespace production
apiVersion: v1
kind: Pod
metadata:
  name: prod-app
  namespace: production
  labels:
    app: web
    env: production
spec:
  terminationGracePeriodSeconds: 45
  securityContext:
    runAsUser: 1000
  containers:
  - name: nginx
    image: nginx:1.25
    ports:
    - containerPort: 80
    env:
    - name: APP_ENV
      value: "production"
    resources:
      requests:
        cpu: "100m"
        memory: "64Mi"
      limits:
        cpu: "200m"
        memory: "128Mi"
    livenessProbe:
      httpGet:
        path: /
        port: 80
      periodSeconds: 10
    readinessProbe:
      httpGet:
        path: /
        port: 80
      periodSeconds: 5
    securityContext:
      readOnlyRootFilesystem: true
    volumeMounts:
    - name: tmp
      mountPath: /tmp
  volumes:
  - name: tmp
    emptyDir: {}
Why emptyDir at /tmp?With readOnlyRootFilesystem: true, the container can't write anywhere. Nginx needs /tmp, /var/cache/nginx, and /var/run to be writable. In the real exam, you'd mount emptyDirs at all writable paths. For this task, /tmp is sufficient.
