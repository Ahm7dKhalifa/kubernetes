01 // BEFORE — NO INGRESS

Before: Two LoadBalancers (The KodeKloud Problem)

This is exactly the diagram from the screenshot. www.my-online-store.com maps to a GCP LoadBalancer. But the shop also needs a Video service. So they added a SECOND LoadBalancer (port 38282). Two separate LBs, two separate IPs, two separate bills, no TLS, no routing control.

🔥
Problem: GCP LB #1 (port 38080) → wear-service → 3× wear pods. GCP LB #2 (port 38282) → video-service → 3× Video pods. No Ingress, no TLS, no path routing. Users must know different ports. Costs ~$150/month for 2 LBs alone.
FULL CLUSTER — BEFORE — Browser → 2× GCP LoadBalancer → NodePort → Service → Pods
Problematic path / expensive LBs
wear pods & service
video pods & service
Cost problem
02 // AFTER — WITH INGRESS CONTROLLER

After: One Ingress Controller, One LoadBalancer

One shared GCP LoadBalancer → nginx Ingress Controller (2 replicas, HA) → routes to wear-service OR video-service based on URL path. TLS terminates at the edge. Both services are ClusterIP-only. NetworkPolicy enforces egress. Full observability.

✅
Solution: www.my-online-store.com/wear → wear-service (ClusterIP). www.my-online-store.com/video → video-service (ClusterIP). One LB shared. TLS via cert-manager. Rate limiting. NetworkPolicy blocks cross-service calls.
FULL CLUSTER — AFTER — Browser → 1 LB → nginx-ingress → path routing → wear/video services → pods
HTTPS Ingress path
wear-service / wear pods
video-service / video pods
Secured / NetworkPolicy enforced

metadata:
  name: nginx-ingress-controller
  namespace: ingress-nginx

  replicas: 2

    matchLabels: { app: ingress-nginx }
  template:
    metadata:
      labels: { app: ingress-nginx }
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/port: "10254"
    spec:
      serviceAccountName: nginx-ingress-sa
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
          - labelSelector:
              matchLabels: { app: ingress-nginx }
            topologyKey: kubernetes.io/hostname
      containers:
      - name: controller
        image: registry.k8s.io/ingress-nginx/controller:v1.9.4
        args:
        - /nginx-ingress-controller
        - --publish-service=ingress-nginx/ingress-nginx-svc
        - --ingress-class=nginx
        - --enable-metrics=true
        ports:
        - { name: http,    containerPort: 80    }
        - { name: https,   containerPort: 443   }
        - { name: metrics, containerPort: 10254 }
        resources:
          requests: { cpu: 100m, memory: 90Mi  }
          limits:   { cpu: 500m, memory: 256Mi }
        livenessProbe:
          httpGet: { path: /healthz, port: 10254 }
        readinessProbe:
          httpGet: { path: /healthz, port: 10254 }
          periodSeconds: 5
        securityContext: { runAsUser: 101 }

# ─────────────────────────────────────────────
# INGRESS RESOURCE — Path routing
# /wear → wear-service, /video → video-service
# TLS auto via cert-manager, rate limiting
# ─────────────────────────────────────────────
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: store-ingress
  namespace: production
  annotations:
    kubernetes.io/ingress.class: "nginx"
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/limit-rps: "100"
    nginx.ingress.kubernetes.io/limit-connections: "20"
    nginx.ingress.kubernetes.io/enable-cors: "true"
    nginx.ingress.kubernetes.io/cors-allow-origin: "https://www.my-online-store.com"
    nginx.ingress.kubernetes.io/proxy-body-size: "50m"
    nginx.ingress.kubernetes.io/rewrite-target: /$2
    nginx.ingress.kubernetes.io/use-regex: "true"
    nginx.ingress.kubernetes.io/configuration-snippet: |
      more_set_headers "X-Content-Type-Options: nosniff";
      more_set_headers "X-Frame-Options: DENY";
      more_set_headers "Strict-Transport-Security: max-age=31536000";
spec:
  tls:
  - hosts: [www.my-online-store.com]
    secretName: store-tls-secret
  rules:
  - host: www.my-online-store.com
    http:
      paths:
      - path: /wear(/|$)(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: wear-service
            port: { number: 80 }
      - path: /video(/|$)(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: video-service
            port: { number: 80 }

# Canary ingress (new version — 5%)
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: video-canary
  namespace: production
  annotations:
    kubernetes.io/ingress.class: "nginx"
    nginx.ingress.kubernetes.io/canary: "true"
    nginx.ingress.kubernetes.io/canary-weight: "5"   # 5% of traffic
        # Alternatively: route by header (for testing)
        # nginx.ingress.kubernetes.io/canary-by-header: "X-Version"
        # nginx.ingress.kubernetes.io/canary-by-header-value: "v2"
spec:
  rules:
  - host: video.my-online-store.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: video-service-v2  # v2.0.0 canary
            port: { number: 80 }
