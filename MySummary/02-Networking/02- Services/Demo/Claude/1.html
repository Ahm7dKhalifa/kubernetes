Architecture Overview
Our full-stack application running on Kubernetes with 3 worker nodes
🌐

Frontend (React/Nginx)

Public-facing web UI exposed via NodePort service. Traffic enters the cluster on any node's IP at a fixed port. Load balanced across 2 replicas.

NodePort :30080
⚙️

Backend (Node.js API)

REST API layer exposed via ClusterIP — only reachable inside the cluster. 5 replicas for high throughput. Frontend calls it via DNS service name.

ClusterIP :8080
🗄️

PostgreSQL (StatefulSet)

Persistent database layer using a StatefulSet with a Headless service. 1 primary + 2 read replicas with ordered, stable pod identity.

Headless :5432
🏗️

Kubernetes Cluster

3-node cluster: 1 control plane + 2 worker nodes. Pods distributed by the scheduler. Each node runs kubelet, kube-proxy, and container runtime.

🌍 User Sends HTTP Request

A user opens a browser and navigates to http://192.168.1.11:30080 — any worker node IP works because NodePort opens the same port on ALL nodes.

  • TCP connection to Node IP on port 30080
  • kube-proxy intercepts via iptables rules
  • Load balanced to frontend pod on any node
  • Works even if frontend pod isn't on that node

🔌 NodePort Service

The NodePort service frontend-svc is defined with type: NodePort. Kubernetes opens port 30080 on ALL node network interfaces automatically.

  • NodePort range: 30000 – 32767
  • Service ClusterIP also assigned internally
  • spec.selector matches pods with label app=frontend
  • Endpoints object tracks pod IPs dynamically

🔧 kube-proxy iptables Rules

kube-proxy watches the API server for Service/Endpoints changes and programs iptables rules on every node. Traffic is DNAT'd from the NodePort to a random pod IP.

  • KUBE-SVC chain matches traffic to service
  • KUBE-SEP chains map to individual pod endpoints
  • Probability-based random selection = round-robin
  • Connection tracking ensures session persistence

🖥️ Frontend Pod Receives Request

The Nginx/React frontend pod handles the HTTP request, serves the static assets, and makes API calls to the backend using the internal DNS name http://backend-svc:8080.

  • Container runs on port 80 (Nginx)
  • Environment variable BACKEND_URL injected via ConfigMap
  • Makes XHR/fetch calls to backend-svc via CoreDNS
  • CPU/Memory limits enforced by kubelet

🔀 ClusterIP Service Routes to Backend

CoreDNS resolves backend-svc.default.svc.cluster.local to the ClusterIP virtual IP. kube-proxy then distributes the connection across all 5 backend pods.

  • ClusterIP is a virtual IP — no real host has it
  • iptables maps VIP → random pod endpoint
  • 5 pods = ~20% traffic each
  • Unhealthy pods auto-removed from Endpoints

⚙️ Backend Pod Processes Request

The Node.js backend pod handles the business logic, validates the request, and queries the PostgreSQL database using the headless service DNS to reach the primary node directly.

  • Connects to postgres-0.postgres-svc:5432 (primary)
  • Reads may go to postgres-1 or postgres-2 (replicas)
  • Secrets mounted for DB credentials
  • Horizontal Pod Autoscaler can scale to 10 replicas

🔍 Headless Service & CoreDNS

The headless service (clusterIP: None) lets CoreDNS return individual pod IPs. StatefulSet pods get stable DNS names like postgres-0.postgres-svc.default.svc.cluster.local.

  • postgres-0 = always the primary candidate
  • DNS A records: one per pod (not a VIP)
  • Ordered startup: 0 → 1 → 2
  • initContainers can detect primary/replica role

💾 Database Write & Response

The backend writes to postgres-0 (primary). PostgreSQL streams WAL logs to both replicas. The response travels back up the chain: DB → Backend → Frontend → User.

  • PersistentVolumeClaim provides durable storage
  • WAL streaming replication to replicas
  • Response: DB → Backend pod → ClusterIP → Frontend → NodePort → User
  • Full round trip completes in <100ms typically

01-frontend-deployment.yaml
# Frontend Deployment — 2 replicas, Nginx serving React build
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend
  namespace: fullstack-app
  labels:
    app: frontend
    tier: web
    version: v1.0.0
spec:
  replicas: 2
  selector:
    matchLabels:
      app: frontend
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 0       # Zero downtime
      maxSurge: 1
  template:
    metadata:
      labels:
        app: frontend
        tier: web
    spec:
      # Spread pods across different nodes
      topologySpreadConstraints:
        - maxSkew: 1
          topologyKey: kubernetes.io/hostname
          whenUnsatisfiable: DoNotSchedule
          labelSelector:
            matchLabels:
              app: frontend
      containers:
        - name: frontend
          image: myregistry/frontend:1.0.0
          imagePullPolicy: Always
          ports:
            - containerPort: 80
              name: http
          envFrom:
            - configMapRef:
                name: app-config
          resources:
            requests:
              cpu: "100m"
              memory: "64Mi"
            limits:
              cpu: "200m"
              memory: "128Mi"
          livenessProbe:
            httpGet:
              path: /healthz
              port: 80
            initialDelaySeconds: 10
            periodSeconds: 15
          readinessProbe:
            httpGet:
              path: /ready
              port: 80
            initialDelaySeconds: 5
            periodSeconds: 10
02-frontend-service.yaml
# NodePort Service — exposes frontend to external traffic on :30080
apiVersion: v1
kind: Service
metadata:
  name: frontend-svc
  namespace: fullstack-app
  labels:
    app: frontend
  annotations:
    description: "NodePort service for external frontend access"
spec:
  type: NodePort           # ← Opens port on every node
  selector:
    app: frontend           # Targets pods with this label
  ports:
    - name: http
      protocol: TCP
      port: 80              # Service port (internal)
      targetPort: 80        # Pod container port
      nodePort: 30080       # External port (30000-32767)
  sessionAffinity: None    # Round-robin load balancing

---
# Access via: http://<ANY-NODE-IP>:30080
# Example: http://192.168.1.11:30080
#          http://192.168.1.12:30080  (same result!)
#          http://192.168.1.13:30080  (same result!)
03-backend-deployment.yaml
# Backend Deployment — 5 replicas, Node.js REST API
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend
  namespace: fullstack-app
  labels:
    app: backend
    tier: api
spec:
  replicas: 5
  selector:
    matchLabels:
      app: backend
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1
      maxSurge: 2
  template:
    metadata:
      labels:
        app: backend
        tier: api
    spec:
      # Anti-affinity: spread pods across different nodes
      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
            - weight: 100
              podAffinityTerm:
                labelSelector:
                  matchLabels:
                    app: backend
                topologyKey: kubernetes.io/hostname
      containers:
        - name: backend
          image: myregistry/backend:1.0.0
          imagePullPolicy: Always
          ports:
            - containerPort: 8080
              name: api
          env:
            - name: NODE_ENV
              value: "production"
            - name: DB_HOST
              valueFrom:
                configMapKeyRef:
                  name: app-config
                  key: DB_HOST
            - name: DB_PORT
              value: "5432"
            - name: DB_NAME
              value: "appdb"
            - name: DB_USER
              valueFrom:
                secretKeyRef:
                  name: db-credentials
                  key: username
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: db-credentials
                  key: password
          resources:
            requests:
              cpu: "250m"
              memory: "128Mi"
            limits:
              cpu: "500m"
              memory: "256Mi"
          livenessProbe:
            httpGet:
              path: /api/health
              port: 8080
            initialDelaySeconds: 15
            periodSeconds: 20
          readinessProbe:
            httpGet:
              path: /api/ready
              port: 8080
            initialDelaySeconds: 10
            periodSeconds: 5

04-backend-service.yaml
# ClusterIP Service — internal-only, no external access
apiVersion: v1
kind: Service
metadata:
  name: backend-svc
  namespace: fullstack-app
  labels:
    app: backend
spec:
  type: ClusterIP           # ← Default type, internal only
  selector:
    app: backend
  ports:
    - name: api
      protocol: TCP
      port: 8080             # Service port
      targetPort: 8080      # Pod container port

# DNS: backend-svc.fullstack-app.svc.cluster.local
# Short: backend-svc (within same namespace)
# ClusterIP: auto-assigned from service CIDR (e.g. 10.96.100.50)
# Frontend calls: http://backend-svc:8080/api
05-postgres-statefulset.yaml
# PostgreSQL StatefulSet — 1 primary + 2 replicas
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgres
  namespace: fullstack-app
  labels:
    app: postgres
    tier: database
spec:
  serviceName: postgres-svc   # Headless service for DNS
  replicas: 3                  # 1 primary + 2 replicas
  selector:
    matchLabels:
      app: postgres
  podManagementPolicy: OrderedReady  # Starts 0→1→2 in order
  updateStrategy:
    type: RollingUpdate
  template:
    metadata:
      labels:
        app: postgres
    spec:
      initContainers:
        # Detect if this pod is primary (index 0) or replica
        - name: init-postgres
          image: postgres:15-alpine
          command:
            - /bin/bash
            - -c
            - |
              #!/bin/bash
              # Get pod ordinal from hostname
              POD_INDEX=${HOSTNAME##*-}
              if [ "$POD_INDEX" = "0" ]; then
                echo "primary" > /mnt/role/role
              else
                echo "replica" > /mnt/role/role
              fi
          volumeMounts:
            - name: role
              mountPath: /mnt/role
      containers:
        - name: postgres
          image: postgres:15-alpine
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 5432
              name: postgres
          env:
            - name: POSTGRES_DB
              value: "appdb"
            - name: POSTGRES_USER
              valueFrom:
                secretKeyRef:
                  name: db-credentials
                  key: username
            - name: POSTGRES_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: db-credentials
                  key: password
            - name: PGDATA
              value: /var/lib/postgresql/data/pgdata
          volumeMounts:
            - name: postgres-data
              mountPath: /var/lib/postgresql/data
            - name: role
              mountPath: /mnt/role
          resources:
            requests:
              cpu: "500m"
              memory: "512Mi"
            limits:
              cpu: "1000m"
              memory: "1Gi"
          livenessProbe:
            exec:
              command:
                - pg_isready
                - -U
                - $(POSTGRES_USER)
            initialDelaySeconds: 30
            periodSeconds: 10
          readinessProbe:
            exec:
              command:
                - pg_isready
                - -U
                - $(POSTGRES_USER)
                - -d
                - $(POSTGRES_DB)
            initialDelaySeconds: 10
            periodSeconds: 5
      volumes:
        - name: role
          emptyDir: {}
  # Each pod gets its OWN persistent volume claim
  volumeClaimTemplates:
    - metadata:
        name: postgres-data
      spec:
        accessModes: ["ReadWriteOnce"]
        storageClassName: fast-ssd
        resources:
          requests:
            storage: 10Gi

# Pod DNS names (stable, survive restarts):
# postgres-0.postgres-svc.fullstack-app.svc.cluster.local → PRIMARY
# postgres-1.postgres-svc.fullstack-app.svc.cluster.local → REPLICA
# postgres-2.postgres-svc.fullstack-app.svc.cluster.local → REPLICA
06-postgres-service.yaml
# Headless Service for StatefulSet — no ClusterIP, direct pod DNS
apiVersion: v1
kind: Service
metadata:
  name: postgres-svc
  namespace: fullstack-app
  labels:
    app: postgres
spec:
  clusterIP: None             # ← This makes it HEADLESS
  selector:
    app: postgres
  ports:
    - name: postgres
      protocol: TCP
      port: 5432
      targetPort: 5432
  publishNotReadyAddresses: true  # Allow discovery during startup

---
# Read-only service pointing to replicas only (using labels)
apiVersion: v1
kind: Service
metadata:
  name: postgres-read-svc
  namespace: fullstack-app
spec:
  clusterIP: None
  selector:
    app: postgres
    role: replica             # Only targets replica pods
  ports:
    - port: 5432
      targetPort: 5432

09-storageclass.yaml
# StorageClass for fast SSD — used by postgres volumeClaimTemplates
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast-ssd
provisioner: kubernetes.io/no-provisioner  # Local (use cloud for prod)
volumeBindingMode: WaitForFirstConsumer
reclaimPolicy: Retain                     # Keep data on pod delete
allowVolumeExpansion: true

---
# PersistentVolumes (one per postgres pod) — for local dev
# In cloud: StorageClass auto-provisions these
apiVersion: v1
kind: PersistentVolume
metadata:
  name: postgres-pv-0
spec:
  storageClassName: fast-ssd
  capacity:
    storage: 10Gi
  accessModes: ["ReadWriteOnce"]
  persistentVolumeReclaimPolicy: Retain
  local:
    path: /mnt/data/postgres-0
  nodeAffinity:
    required:
      nodeSelectorTerms:
        - matchExpressions:
            - key: kubernetes.io/hostname
              operator: In
              values: [worker-node-01]
---
# Repeat for postgres-pv-1 (worker-node-02) and postgres-pv-2 (worker-node-03)

How PostgreSQL primary/replica topology works in Kubernetes

Pod namesRandom (e.g. backend-7c8b-x2k9)Stable ordinal (postgres-0, postgres-1)
Pod identityInterchangeableUnique, stable per pod
StorageShared or ephemeralDedicated PVC per pod (persists)
Startup orderAll at once (parallel)Ordered (0 → 1 → 2)

Delete behaviorPVC deleted with podPVC kept after pod deletion
Rolling updatemaxSurge / maxUnavailableOne pod at a time, highest ordinal first
