How port mapping works: A Service's port is what clients connect to. The targetPort is what the container actually listens on (can differ). The nodePort (NodePort only) is the port opened on every node's network interface. kube-proxy programs iptables rules to DNAT traffic from nodeIP:nodePort → clusterIP:port → podIP:targetPort.
Section 03
YAML with Port Annotations
Every port field annotated, showing exactly how it connects to the container, the pod, and the service discovery layer.
frontend-service.yaml
# NodePort Service — opens port 30080 on EVERY node's NIC
apiVersion: v1
kind: Service
metadata:
  name: frontend-svc
  namespace: app
spec:
  type: NodePort               # Opens nodePort on 192.168.1.11, .12, .13
  selector:
    app: frontend               # Matches pods with label app=frontend
                                  # → 10.244.1.5 and 10.244.2.3 (Endpoints)
  ports:
    - name: http
      protocol: TCP
      port: 80                   # ← Service port (ClusterIP:80)
      targetPort: 80            # ← Container's containerPort (nginx :80)
      nodePort: 30080           # ← External: nodeIP:30080 (any of the 3 nodes)
                                  # Range must be 30000-32767
  sessionAffinity: None       # Round-robin across both frontend pods

# Port flow:
# Browser → 192.168.1.11:30080
#          kube-proxy iptables DNAT
#          → 10.96.10.5:80  (ClusterIP)
#          → 10.244.1.5:80  (frontend-dep-7d9f-xk2p, nginx container)
#          OR 10.244.2.3:80  (frontend-dep-7d9f-wz7t, nginx container)
backend-service.yaml
# ClusterIP — no external exposure, only reachable inside cluster
apiVersion: v1
kind: Service
metadata:
  name: backend-svc
  namespace: app
spec:
  type: ClusterIP              # Default — gets VIP 10.96.20.14
  selector:
    app: backend               # Matches all 5 backend pods:
                                 # 10.244.1.8  backend-dep-5c7b-mn4q
                                 # 10.244.1.12 backend-dep-5c7b-pw6r
                                 # 10.244.2.7  backend-dep-5c7b-hj5s
                                 # 10.244.2.11 backend-dep-5c7b-qt1v
                                 # 10.244.3.4  backend-dep-5c7b-lm8a
  ports:
    - name: api
      protocol: TCP
      port: 8080                # ← Service port: backend-svc:8080
      targetPort: 8080         # ← Pod containerPort (node.js listens :8080)

# DNS inside cluster: backend-svc.app.svc.cluster.local
# Frontend calls: http://backend-svc:8080/api/users
#   → CoreDNS resolves → 10.96.20.14
#   → kube-proxy iptables → random backend pod :8080
#
# To verify endpoints:
#   kubectl get endpoints backend-svc -n app
frontend-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend-dep
  namespace: app
spec:
  replicas: 2                   # → 2 pods: xk2p (node1) + wz7t (node2)
  selector:
    matchLabels:
      app: frontend             # Must match Service selector
  template:
    metadata:
      labels:
        app: frontend           # Picked up by frontend-svc selector
    spec:
      topologySpreadConstraints:  # Spread across nodes for HA
        - maxSkew: 1
          topologyKey: kubernetes.io/hostname
          whenUnsatisfiable: DoNotSchedule
          labelSelector:
            matchLabels:
              app: frontend
      containers:
        - name: nginx
          image: nginx:1.25-alpine    # Actual container image
          ports:
            - name: http
              containerPort: 80      # ← THIS is what targetPort:80 maps to
              protocol: TCP
          env:
            - name: BACKEND_URL
              value: "http://backend-svc:8080"  # DNS name of backend ClusterIP
          resources:
            requests:
              cpu: "100m"
              memory: "64Mi"
            limits:
              cpu: "200m"
              memory: "128Mi"
          livenessProbe:
            httpGet:
              path: /healthz
              port: 80             # kubelet probes :80 directly on pod IP

        - name: envoy-sidecar     # Service mesh sidecar
          image: envoyproxy/envoy:v1.28
          ports:
            - containerPort: 15001  # ← Envoy proxy port (not exposed via Service)
              protocol: TCP
backend-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend-dep
  namespace: app
spec:
  replicas: 5                   # → mn4q pw6r hj5s qt1v lm8a

    matchLabels:
      app: backend
  template:

      affinity:
        podAntiAffinity:         # Prefer different nodes

            - weight: 100
              podAffinityTerm:
                labelSelector:
                  matchLabels:
                    app: backend
                topologyKey: kubernetes.io/hostname
      containers:
        - name: backend-api
          image: myrepo/backend-api:2.1.0   # Real image tag
          ports:
            - name: api
              containerPort: 8080           # ← THIS is what targetPort:8080 maps to
              protocol: TCP
          env:
            - name: DB_HOST
              value: "postgres-0.postgres-svc.app.svc.cluster.local"  # Stable DNS
            - name: DB_HOST_READ
              value: "postgres-svc.app.svc.cluster.local"           # Round-robin replicas
            - name: DB_PORT
              value: "5432"                 # Container port of postgres
            - name: DB_NAME
              value: "appdb"
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: db-secret
                  key: password
          livenessProbe:
            httpGet:
              path: /health
              port: 8080               # kubelet probes pod IP :8080 directly
            initialDelaySeconds: 15
            periodSeconds: 20
          readinessProbe:
            httpGet:
              path: /ready
              port: 8080               # Pod removed from Endpoints if not ready
            initialDelaySeconds: 8
          resources:
            requests: { cpu: "250m", memory: "128Mi" }
            limits:   { cpu: "500m", memory: "256Mi" }
postgres-statefulset.yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgres                 # → pods: postgres-0, postgres-1, postgres-2
  namespace: app
spec:
  serviceName: "postgres-svc"   # Headless service for stable DNS
  replicas: 3                   # postgres-0=PRIMARY  postgres-1,2=REPLICA
  podManagementPolicy: OrderedReady # Start 0→1→2, stop 2→1→0
  selector:
    matchLabels:
      app: postgres
  template:
    metadata:
      labels:
        app: postgres           # Matched by postgres-svc selector
    spec:
      containers:
        - name: postgres
          image: postgres:15.4-alpine   # Exact version pinned
          ports:
            - name: postgres
              containerPort: 5432       # ← THIS is what targetPort:5432 maps to
              protocol: TCP              #   postgres-svc targets this via selector
          env:
            - name: POSTGRES_DB
              value: "appdb"
            - name: POSTGRES_USER
              valueFrom:
                secretKeyRef: { name: db-secret, key: username }
            - name: POSTGRES_PASSWORD
              valueFrom:
                secretKeyRef: { name: db-secret, key: password }
            - name: PGDATA
              value: /var/lib/postgresql/data/pgdata
          volumeMounts:
            - name: postgres-data
              mountPath: /var/lib/postgresql/data
          readinessProbe:
            exec:
              command: ["pg_isready", "-U", "$(POSTGRES_USER)", "-p", "5432"]
                                             # Checks :5432 is accepting connections
            initialDelaySeconds: 20
            periodSeconds: 10
          resources:
            requests: { cpu: "500m", memory: "512Mi" }
            limits:   { cpu: "1",     memory: "1Gi"   }
  volumeClaimTemplates:          # Creates 1 PVC per pod, binds to that pod only
    - metadata:
        name: postgres-data       # → postgres-data-postgres-0
      spec:                       #   postgres-data-postgres-1
        accessModes: ["ReadWriteOnce"]  # postgres-data-postgres-2
        storageClassName: fast-ssd
        resources:
          requests:
            storage: 10Gi
postgres-service.yaml
# Headless Service — clusterIP: None means NO virtual IP assigned
# CoreDNS returns individual pod A records instead of a single VIP
apiVersion: v1
kind: Service
metadata:
  name: postgres-svc
  namespace: app
spec:
  clusterIP: None               # ← HEADLESS: no VIP, DNS returns pod IPs
  selector:
    app: postgres               # Matches postgres-0, postgres-1, postgres-2
  ports:
    - name: postgres
      protocol: TCP
      port: 5432                 # ← Service port (same as container port here)
      targetPort: 5432           # ← Container's containerPort: 5432
  publishNotReadyAddresses: true # Include unready pods in DNS (for init)

# DNS names created for each StatefulSet pod:
#
#  postgres-0.postgres-svc.app.svc.cluster.local → 10.244.1.20 (PRIMARY RW)
#  postgres-1.postgres-svc.app.svc.cluster.local → 10.244.2.18 (REPLICA RO)
#  postgres-2.postgres-svc.app.svc.cluster.local → 10.244.3.15 (REPLICA RO)
#
# Backend uses postgres-0.postgres-svc for WRITES
# Backend uses postgres-svc (round-robin) for READS
#
# Verify: kubectl exec -it backend-dep-5c7b-mn4q -n app -- \
#         nslookup postgres-0.postgres-svc.app.svc.cluster.local
Section 04
Full Request Cycle
Trace a single HTTP POST request from browser to database and back — every hop, every port, every IP, every component.
01
Browser sends HTTP request
The user types http://192.168.1.11:30080/app in their browser. TCP SYN is sent to worker-node-01's external IP on port 30080.
TCP SYN → 192.168.1.11:30080
Source: client-machine:54312
Protocol: HTTP/1.1 GET / HTTP/2
nodePort 30080 is open on ALL 3 nodes — any node IP works
02
kube-proxy intercepts — iptables DNAT
kube-proxy on worker-node-01 has programmed iptables rules. Traffic hitting port 30080 on any interface is intercepted and DNAT'd to the Service's ClusterIP, then to a random pod endpoint.
iptables -t nat -A KUBE-NODEPORTS -p tcp --dport 30080 -j KUBE-SVC-frontend
iptables DNAT: 192.168.1.11:30080 → 10.96.10.5:80 (ClusterIP)
iptables DNAT: 10.96.10.5:80 → 10.244.1.5:80 (50% probability)
OR: 10.96.10.5:80 → 10.244.2.3:80 (50% probability)
03
Frontend Pod receives request at :80
The packet arrives at frontend pod frontend-dep-7d9f-xk2p (IP 10.244.1.5) on worker-node-01. The nginx container is listening on containerPort 80 and serves the React app.
10.244.1.5:80 → nginx:1.25-alpine container
Pod: frontend-dep-7d9f-xk2p
Node: worker-node-01 (192.168.1.11)
nginx serves /index.html, loads React bundle
React app boots, makes API call to backend...
04
Frontend calls API — DNS resolution
React app makes fetch('http://backend-svc:8080/api/users'). The pod's resolv.conf points to CoreDNS at 10.96.0.10. CoreDNS resolves the name to the ClusterIP.
resolv.conf: nameserver 10.96.0.10 (CoreDNS ClusterIP)
DNS query: backend-svc.app.svc.cluster.local
CoreDNS responds: A record → 10.96.20.14 (ClusterIP)
TCP connect: 10.244.1.5:random → 10.96.20.14:8080
05
ClusterIP routes to a Backend Pod
kube-proxy's iptables rules DNAT the ClusterIP to one of the 5 backend pod endpoints (20% probability each). The packet is forwarded to the selected backend pod's real IP.
DNAT: 10.96.20.14:8080 → 10.244.2.7:8080 (20% — backend-dep-5c7b-hj5s)
Other endpoints:
10.244.1.8 backend-dep-5c7b-mn4q
10.244.1.12 backend-dep-5c7b-pw6r
10.244.2.11 backend-dep-5c7b-qt1v
10.244.3.4 backend-dep-5c7b-lm8a
06
Backend Pod processes request at :8080
The Node.js container on pod backend-dep-5c7b-hj5s (IP 10.244.2.7, worker-node-02) handles the API request. It validates, authenticates, and needs to query the database.
10.244.2.7:8080 → node:20-alpine container (app.js)
Pod: backend-dep-5c7b-hj5s
Node: worker-node-02 (192.168.1.12)
Connects to DB via env.DB_HOST:
postgres-0.postgres-svc.app.svc.cluster.local
07
Headless DNS — resolve postgres-0 directly
Unlike ClusterIP, the headless service returns actual pod IPs. CoreDNS gives back the IP of postgres-0 directly — no VIP, no iptables DNAT. The backend connects straight to the primary pod.
DNS query: postgres-0.postgres-svc.app.svc.cluster.local
CoreDNS returns: A record → 10.244.1.20 (direct pod IP!)
No iptables involved — packet goes directly to pod
TCP connect: 10.244.2.7:random → 10.244.1.20:5432
08
PostgreSQL primary executes the query
The postgres container on pod postgres-0 receives the SQL query, executes it, streams WAL changes to replicas, and returns results.
10.244.1.20:5432 → postgres:15.4-alpine container
Pod: postgres-0 (PRIMARY, ReadWrite)
Node: worker-node-01 (192.168.1.11)
PVC: postgres-data-postgres-0 (10Gi /var/lib/postgresql/data)
WAL streamed → 10.244.2.18:5432 (postgres-1)
WAL streamed → 10.244.3.15:5432 (postgres-2)
09
Response travels back — same path reversed
The SQL result travels back through the network. The backend serialises it as JSON and returns the HTTP 200 response. kube-proxy translates IPs back (un-DNAT) so the frontend sees a clean response.
10.244.1.20:5432 → SQL rows → 10.244.2.7:8080 (backend)
10.244.2.7:8080 → JSON response → 10.244.1.5:80 (frontend)
10.244.1.5:80 → HTML/JSON → 192.168.1.11:30080 (node)
192.168.1.11:30080 → Browser 200 OK ✓
Total RTT (local cluster): ~3–8ms
